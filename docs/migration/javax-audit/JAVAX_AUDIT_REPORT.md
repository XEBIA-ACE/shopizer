## Definitions and limitations

- **reference**: One textual javax.* occurrence in Java code (import, static/wildcard import, or inline fully-qualified name). Comments and string literals are ignored. Each reference is one edit in a namespace migration.
- **annotation_usage**: An @Annotation site whose simple name is bound to a single-type javax.* import in the same file. Not an edit by itself (it follows the import), reported to size the annotation surface.
- **migration_required**: yes when the type moved to jakarta.* in Jakarta EE 9+ (Spring Boot 3); no when it is part of the JDK (e.g. javax.crypto, javax.imageio).
- **layer**: Heuristic from package path / file name, first match wins: repository (repository|repositories|dao, *Repository*), service (service|services|facade|modules, *Service*, *Facade*), controller (controller|api|filter|rest, *Controller, *Api, *Filter), configuration (config|configuration|application, *Config*, *Application), model/DTO (sm-core-model, sm-shop-model, model|entity|dto packages), else other.
- Scope is every `*.java` file in the repository (main and test sources of the five modules, plus build tooling under `.mvn/`), excluding `target/` build output. Non-Java resources (XML, properties, templates) and transitive dependencies that use javax.* internally are not covered and must be assessed in S8.
- Annotation usages are only resolved for single-type imports; wildcard imports and same-named types from other packages are not resolved (none occur in this codebase at this commit).
- Layer assignment is a path/name heuristic; per-file layers are listed in `javax-audit-summary.json` for review.
